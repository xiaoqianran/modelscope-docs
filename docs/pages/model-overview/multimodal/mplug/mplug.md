# Model Overview

Multimodal pre-trained models are commonly used to address multimodal tasks. These models, trained on large amounts of unsupervised image-text data, demonstrate significant improvements on downstream multimodal tasks. Addressing current challenges in multimodal fusion approaches—1) training and inference efficiency, and 2) information asymmetry between modalities—we propose mPLUG, a novel multimodal foundation model with a new paradigm for modality alignment and fusion. The mPLUG model employs a more efficient Skip-connected Network architecture with Inter-layer Shortcuts that bypass the time-consuming Self-Attention in visual modules, enabling cross-layer/cross-semantic fusion between different modalities while also alleviating the vanishing gradient problem.

![model](./_resources/mplug.png)

For more detailed information about this model, please refer to the paper. The abstract is as follows:

```text
Large-scale pre-trained foundation models have become a new paradigm for building artificial intelligence (AI) systems and can be rapidly applied to a wide range of downstream tasks. In this paper, we present mPLUG, a novel multimodal foundation model designed for cross-modal understanding and generation. Most existing pre-trained models face challenges in training and inference efficiency, as well as semantic information being obscured by long visual sequences during cross-modal alignment. mPLUG introduces a multimodal architecture based on an efficient skip-connections network. mPLUG is pre-trained end-to-end on large-scale image-text pairs with both discriminative and generative objectives. It achieves state-of-the-art results across a wide range of vision-language downstream tasks, including image captioning, image-text retrieval, visual grounding, and visual question answering, while also demonstrating strong zero-shot transferability across both image-text and video-text tasks.
```


Model Advantages:

    1. The mPLUG model proposes a more efficient Skip-connected Network paradigm for modality alignment and fusion. Through Inter-layer Shortcuts that bypass the time-consuming Self-Attention in visual modules, it enables cross-layer/cross-semantic fusion between different modalities and alleviates the vanishing gradient problem.
    2. Trained on large amounts of unsupervised Chinese and English corpora, resulting in both Chinese and English versions, as well as models with different parameter sizes.
    3. The model achieves SOTA performance on multiple Chinese and English multimodal understanding/generation tasks, including Cross-modal Retrieval, Image Caption, VQA, and Visual Grounding. It also achieves SOTA results on multiple zero-shot image-text/video-text tasks, including NoCaps, Cross-modal Retrieval, Video Retrieval, Video QA, and Video Caption.



# Model Configuration

The hyperparameters for the mPLUG model can be found in the config.yaml file within the downloaded model directory. The general format is as follows:

```text
task: 'visual-question-answering'
bert_config: 'config_bert.json'

image_res: 384
vision_width: 768
distill: True
clip_name: "ViT-L-14"

# predictor
min_length: 1
max_length: 10
beam_size: 5

# clip
clip_embed_dim: 768
clip_image_resolution: 224
clip_vision_layers: 24
clip_vision_width: 1024
clip_vision_patch_size: 14
clip_context_length: 77
clip_vocab_size: 49408
clip_transformer_width: 768
clip_transformer_heads: 12
clip_transformer_layers: 12
```
In pre-trained models, these configurations represent only a portion of the complete model configuration. The PALM model parameters are passed through the PalmConfig class. Below are the commonly used configuration items listed in the API documentation:

## Parameter List


* **task** (`str`, optional, defaults to "visual-question-answering") - Task names supported by mPLUG model, `"visual-question-answering"`, `"image-captioning"` and `"image_text_retrieval"` are supported.


* **bert_config** (`str`, optional, defaults to "config_bert.json") - The natural language understanding part of the model uses BertModel, this parameter determines the configuration file name of BertModel.


* **image_res** (`int`, optional, defaults to 384) - The resolution of input images.


* **vision_width** (`int`, optional, defaults to 768) – Dimensionality of the encoder layers and the pooler layer.


* **distill** (`bool`, optional, defaults to True) – Whether to add a distillation structure to the model.


* **clip_name** (`str`, optional, defaults to "ViT-L-14") – The name of CLIP when initializing the model.


* **min_length** (`int`, optional, defaults to 1) - Minimum length of token generated by the generator.


* **max_length** (`int`, optional, defaults to 10) - Maximum length of token generated by the generator.


* **beam_size** (`int`, optional, defaults to 5) - The parameter in the beam search algorithm which determines how many of the best partial solutions to evaluate.


* **clip_embed_dim** (`int`, optional, defaults to 768) – Dimensionality of the embedding layers.


* **clip_image_resolution** (`int`, optional, defaults to 224) – The resolution of input images which input into CLIP model.



* **clip_vision_layers** (`int`, optional, defaults to 24) – Number of hidden layers in the CLIP vision encoder.


* **clip_vision_width** (`int`, optional, defaults to 1024) – Dimensionality of the CLIP vision encoder layers.


* **clip_vision_patch_size** (`int`, optional, defaults to 14) – The size (resolution) of each patch.


* **clip_context_length** (`int`, optional, defaults to 77) – The context length of CLIP.


* **clip_vocab_size** (`int`, optional, defaults to 30522) – Vocabulary size of the CLIP model. Defines the number of different tokens that can be represented by the `inputs_ids` passed when calling `MPLUG`.


* **clip_transformer_width** (`int`, optional, defaults to 768) – Dimensionality of the CLIP Transformer layers.


* **clip_transformer_heads** (`int`, optional, defaults to 12) – Number of attention heads for each attention layer in the Transformer layers.


* **clip_transformer_layers** (`int`, optional, defaults to 12) – Number of hidden layers in the CLIP Transformer model.


When using mPLUG models for inference, these parameters are generally fixed. You can directly load the model using the Model class:
```python

```

# Model Preprocessing

## Preprocessor

When using mPLUG within the ModelScope framework, ModelScope recommends using the preprocessor.
ModelScope's preprocessor provides specialized encapsulation for various tasks and directly interfaces with the dataset module (the preprocessor handles data fetching, tokenization, tensor conversion, label analysis, etc.), eliminating the need to write different adapter code for each task.

Within the ModelScope framework, we provide a unified preprocessor for multiple downstream tasks of mPLUG:

```python
from modelscope.hub.snapshot_download import snapshot_download
from modelscope.preprocessors import MPlugPreprocessor

model_id = 'damo/mplug_visual-question-answering_coco_large_en'
model_dir = snapshot_download(model_id)
input_vqa = {
    'image': 'https://alice-open.oss-cn-zhangjiakou.aliyuncs.com/mPLUG/image_mplug_vqa.jpg',
    'question': 'What is the woman doing?',
}

preprocessor = MPlugPreprocessor(model_dir)
# The preprocessor can be used directly via the __call__ method
result = preprocessor(input_vqa)
print(result)
```

Constructor Parameters:


* **model_dir** (`str`) – The model_dir to load the configuration from. Note that this model_dir must exist in the local file system.

* **mode** (`str`, optional, defaults to ‘inference’) – The work mode for this preprocessor. Valid values can be ‘train’, ‘eval’ and ‘inference’.
This preprocessor’s behavior may be different under these values.

* **kwargs** (`dict`, optional)

    sequence_length: The input sequence length to padding to.

    first_sequence: The key for the first sequence

    second_sequence: The key for the second sequence

    label: The label key

    label2id: An optional label2id mapping, the class will try to call utils.parse_label_mapping if this mapping is not supplied.

    Other input args will be fed into the tokenizer at the runtime.

The MPlugPreprocessor accepts input types including Image, str, tuple, and dict. When the user input is a string, it can be either a local image path or an image URL. Tuples should be input as (Image, text), and dictionaries should be input as {'image': Image, 'text': text}. The Image in all cases can be either an image path or an image URL.

For comprehensive usage of the Preprocessor, please refer to [here](https://www.modelscope.ai/docs/Data%20Preprocessing).

# Supported Downstream Tasks

## Visual Question Answering Task

Visual Question Answering (VQA) is a learning task that involves both computer vision and natural language processing. This task is defined as follows: a VQA system takes an image and a free-form, open-ended natural language question about the image as input, and generates a natural language answer as output. Simply put, VQA involves answering questions about a given image.

### Visual Question Answering Task Model

The MPlugForAllTasks class of mPLUG can load specific task models such as visual question answering for training and inference.

```python
from modelscope.models.multi_modal import MPlugForAllTasks
# Load mPLUG Visual Question Answering model
model = MPlugForAllTasks.from_pretrained('damo/mplug_visual-question-answering_coco_large_en')
```

#### Model forward Parameters


* **image** (`torch.FloatTensor` of shape `(batch_size, sequence_length)`) – The image data output by the preprocessor running.

* **question** (`transformers.tokenization_utils_base.BatchEncoding`) – Question data processed by tokenizer, including:

    * **input_ids** (`torch.LongTensor` of shape `(batch_size, sequence_length)`) – Indices of input sequence tokens in the vocabulary.

    * **attention_mask** (`torch.FloatTensor` of shape `(batch_size, sequence_length)`, optional) – Mask to avoid performing attention on padding token indices. Mask values selected in `[0, 1]`:

        1 for tokens that are **not masked**,

        0 for tokens that are **masked**.

    * **token_type_ids** (`torch.LongTensor` of shape `(batch_size, sequence_length)`, optional) – Segment token indices to indicate first and second portions of the inputs. Indices are selected in `[0, 1]`:

        0 corresponds to a sentence A token,

        1 corresponds to a sentence B token.

* **answer** (`Optional[transformers.tokenization_utils_base.BatchEncoding]`, optional, defaults to None) - Answer data processed by tokenizer, similar to question.

## Image-Text Retrieval Task

Image-text retrieval belongs to cross-modal retrieval and is one of the most fundamental tasks in cross-modal understanding. It uses one type of data as a query to retrieve another type of data. Taking images and text as two modalities as an example, the heterogeneous gap refers to the challenge that images and text have inconsistent representation forms and exist in different distribution spaces, making direct similarity measurement impossible, thus presenting a challenging task.

from modelscope.models import Model
model = Model.from_pretrained('damo/mplug_visual-question-answering_coco_large_en')

# Model Training

mPLUG model training can be performed using the trainer provided by ModelScope. The following code demonstrates a complete model training process:

```python
import tempfile
from modelscope.msdatasets import MsDataset
from modelscope.trainers import EpochBasedTrainer, build_trainer

# Use a small subset of the COCO dataset for training
datadict = MsDataset.load('coco_captions_small_slice')

# Rename dataset fields to match model input requirements
train_dataset = MsDataset(datadict['train'].to_hf_dataset().map(
        lambda _: {
            'question': 'what the picture describes?'
    }).rename_column('image:FILE',
                     'image').rename_column('answer:Value', 'answer'))
test_dataset = MsDataset(datadict['test'].to_hf_dataset().map(
        lambda _: {
            'question': 'what the picture describes?'
    }).rename_column('image:FILE',
                     'image').rename_column('answer:Value', 'answer'))

max_epochs = 3
tmp_dir = tempfile.TemporaryDirectory().name

# This function can be used to modify hook behavior during trainer execution
def _cfg_modify_fn(self, cfg):
    cfg.train.hooks = [{
        'type': 'CheckpointHook',
        'interval': max_epochs
    }, {
        'type': 'TextLoggerHook',
        'interval': 1
    }, {
        'type': 'IterTimerHook'
    }]
    return cfg

kwargs = dict(
    model='damo/mplug_visual-question-answering_coco_large_en',
    train_dataset=train_dataset,
    eval_dataset=test_dataset,
    max_epochs=max_epochs,
    work_dir=tmp_dir,
    cfg_modify_fn=_cfg_modify_fn)

# Construct trainer and perform training
trainer: EpochBasedTrainer = build_trainer(
    name=Trainers.nlp_base_trainer, default_args=kwargs)
trainer.train()
```

After training, the work_dir will contain training process files (for resuming training from checkpoints) and inference files (for uploading to ModelHub or for inference/export scenarios).
For specific training details and usage of output files, please refer to the [Model Training Documentation](https://www.modelscope.ai/docs/Model%20Training).
