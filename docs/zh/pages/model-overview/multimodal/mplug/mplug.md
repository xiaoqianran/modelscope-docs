# 模型概览

多模态预训练模型是目前解决多模态任务常采用的模型，通过大量无监督图文数据训练得到的多模态预训练模型，在下游的多模态任务上提升明显。针对当前多模态融合方式存在的问题：1）训练和推理效率； 2）模态间信息不对称问题； 我们提出一种模态对齐融合新范式mPLUG模型，通过更高效的模态对齐融合新范式Skip-connected Network，通过Inter-layer Shortcuts跳过耗时的视觉模块的Self-Attention，使得不同模态可以进行跨层/跨语义融合，也可以缓解梯度消失问题；

![model](./_resources/mplug.png)

关于该模型更多细节介绍可以前往论文了解，论文的摘要信息如下：

```text
大规模预训练基础模型已成为构建人工智能 (AI) 系统的新范式，并且能够快速的应用到广泛的下游任务。本文提出的mPLUG模型，是一个用于跨模态理解和生成的全新的多模态基础模型。大多数现在的预训练模型存在训练和推理效率，以及跨模态对齐中存在语义信息被长视觉序列掩盖的问题。mPLUG提出一个基于高效的skip-connections网络的多模态结构。mPLUG在大规模的图文对上进行端到端的预训练，并且以判别和生成作为优化目标。它在广泛的视觉语言下游任务上实现了最先进的结果，包括图像描述、图文检索、视觉定位和视觉问答等，并且还展示了图片-文本和视频-文本任务的强大的零样本可迁移性。
```


模型领先性：

    1. mPLUG模型提出一种更高效的模态对齐融合新范式Skip-connected Network，通过Inter-layer Shortcuts跳过耗时的视觉模块的Self-Attention，使得不同模态可以进行跨层/跨语义融合，也可以缓解梯度消失问题；
    2. 利用大量中文和英文的无监督语料训练得到了中、英不同版本，同时也有不同参数size的模型。
    3. 模型在多个中英文多模态理解/生成任务上取得SOTA，包括Cross-modal Retrieval，Image Caption，VQA，Visual Grouding；在多个Zero-Shot图文/视频文本任务上取得SOTA，包括NoCaps，Cross-modal Retrieval，Video Retrieval，Video QA，Video Caption；



# 模型配置项

mPLUG模型的超参数控制可以在下载下来的模型文件中找到config.yaml文件，该文件一般格式如下：

```text
task: 'visual-question-answering'
bert_config: 'config_bert.json'

image_res: 384
vision_width: 768
distill: True
clip_name: "ViT-L-14"

# predictor
min_length: 1
max_length: 10
beam_size: 5

# clip
clip_embed_dim: 768
clip_image_resolution: 224
clip_vision_layers: 24
clip_vision_width: 1024
clip_vision_patch_size: 14
clip_context_length: 77
clip_vocab_size: 49408
clip_transformer_width: 768
clip_transformer_heads: 12
clip_transformer_layers: 12
```
在预训练模型中，这些配置只是模型全部配置中的一部分。PALM的模型参数会通过PalmConfig类传入，下面是API文档中列举的常用的配置项：

## 参数列表


* **task** (`str`, optional, defaults to "visual-question-answering") - Task names supported by mPLUG model, `"visual-question-answering"`, `"image-captioning"` and `"image_text_retrieval"` are supported.


* **bert_config** (`str`, optional, defaults to "config_bert.json") - The natural language understanding part of the model uses BertModel, this parameter determines the configuration file name of BertModel.


* **image_res** (`int`, optional, defaults to 384) - The resolution of input images.


* **vision_width** (`int`, optional, defaults to 768) – Dimensionality of the encoder layers and the pooler layer.


* **distill** (`bool`, optional, defaults to True) – Whether to add a distillation structure to the model.


* **clip_name** (`str`, optional, defaults to "ViT-L-14") – The name of CLIP when initializing the model.


* **min_length** (`int`, optional, defaults to 1) - Minimum length of token generated by the generator.


* **max_length** (`int`, optional, defaults to 10) - Maximum length of token generated by the generator.


* **beam_size** (`int`, optional, defaults to 5) - The parameter in the beam search algorithm which determines how many of the best partial solutions to evaluate.


* **clip_embed_dim** (`int`, optional, defaults to 768) – Dimensionality of the embedding layers.


* **clip_image_resolution** (`int`, optional, defaults to 224) – The resolution of input images which input into CLIP model.



* **clip_vision_layers** (`int`, optional, defaults to 24) – Number of hidden layers in the CLIP vision encoder.


* **clip_vision_width** (`int`, optional, defaults to 1024) – Dimensionality of the CLIP vision encoder layers.


* **clip_vision_patch_size** (`int`, optional, defaults to 14) – The size (resolution) of each patch.


* **clip_context_length** (`int`, optional, defaults to 77) – The context length of CLIP.


* **clip_vocab_size** (`int`, optional, defaults to 30522) – Vocabulary size of the CLIP model. Defines the number of different tokens that can be represented by the `inputs_ids` passed when calling `MPLUG`.


* **clip_transformer_width** (`int`, optional, defaults to 768) – Dimensionality of the CLIP Transformer layers.


* **clip_transformer_heads** (`int`, optional, defaults to 12) – Number of attention heads for each attention layer in the Transformer layers.


* **clip_transformer_layers** (`int`, optional, defaults to 12) – Number of hidden layers in the CLIP Transformer model.


当用户在推理中使用mPLUG的模型时，这些参数一般都是固定的。您可以使用Model类直接拉起模型：
```python
from modelscope.models import Model
model = Model.from_pretrained('damo/mplug_visual-question-answering_coco_large_en')
```

如果您使用ModelScope的trainer进行训练，ModelScope推荐您在trainer中对模型参数等进行配置和调节。训练过程可以参考下文“模型的训练”。

# 模型前处理

## 前处理器（Preprocessor）

如果您在ModelScope框架中使用mPLUG，ModelScope建议您使用前处理器。
ModelScope的前处理器对各类任务进行了特化封装，并直接对接数据集模块（前处理器承载了取数据、tokenize数据、tensor化、分析label等功能），因此您不需要为每个任务编写不同的适配代码。

在ModelScope框架中，我们为mPLUG的多个下游任务提供了统一的前处理器：

```python
from modelscope.hub.snapshot_download import snapshot_download
from modelscope.preprocessors import MPlugPreprocessor

model_id = 'damo/mplug_visual-question-answering_coco_large_en'
model_dir = snapshot_download(model_id)
input_vqa = {
    'image': 'https://alice-open.oss-cn-zhangjiakou.aliyuncs.com/mPLUG/image_mplug_vqa.jpg',
    'question': 'What is the woman doing?',
}

preprocessor = MPlugPreprocessor(model_dir)
# 前处理器可以通过__call__方法直接使用
result = preprocessor(input_vqa)
print(result)
```

构造参数:


* **model_dir** (`str`) – The model_dir to load the configuration from. Note that this model_dir must exist in the local file system.

* **mode** (`str`, optional, defaults to ‘inference’) – The work mode for this preprocessor. Valid values can be ‘train’, ‘eval’ and ‘inference’.
This preprocessor’s behavior may be different under these values.

* **kwargs** (`dict`, optional) 
    
    sequence_length: The input sequence length to padding to.

    first_sequence: The key for the first sequence

    second_sequence: The key for the second sequence

    label: The label key

    label2id: An optional label2id mapping, the class will try to call utils.parse_label_mapping if this mapping is not supplied.

    Other input args will be fed into the tokenizer at the runtime.

MPlugPreprocessor前处理器可接受的参数类型有Image、str、tuple、dict。当用户的输入是str时，可以是本地图片路径或图片的url，tuple需要以(Image, text)的方式输入，dict需要以{'image': Image, 'text': text}的方式输入。上述Image均可为图片路径或图片url。

有关Preprocessor的整体使用可以参考[这里](https://www.modelscope.cn/docs/%E6%95%B0%E6%8D%AE%E7%9A%84%E9%A2%84%E5%A4%84%E7%90%86)。

# 模型支持的下游任务

## 视觉问答任务

视觉问答（Visual Question Answering，VQA），是一种涉及计算机视觉和自然语言处理的学习任务。这一任务的定义如下：一个VQA系统以一张图片和一个关于这张图片形式自由、开放式的自然语言问题作为输入，以生成一条自然语言答案作为输出。简单来说，VQA就是给定的图片进行问答。

### 视觉问答任务的模型

mPLUG的MPlugForAllTasks类可以将视觉问答等具体任务模型加载起来用于训练和推理。

```python
from modelscope.models.multi_modal import MPlugForAllTasks
# 加载 mPLUG 视觉问答模型
model = MPlugForAllTasks.from_pretrained('damo/mplug_visual-question-answering_coco_large_en')
```

#### 模型forward参数

    
* **image** (`torch.FloatTensor` of shape `(batch_size, sequence_length)`) – The image data output by the preprocessor running.

* **question** (`transformers.tokenization_utils_base.BatchEncoding`) – Question data processed by tokenizer, including:

    * **input_ids** (`torch.LongTensor` of shape `(batch_size, sequence_length)`) – Indices of input sequence tokens in the vocabulary.

    * **attention_mask** (`torch.FloatTensor` of shape `(batch_size, sequence_length)`, optional) – Mask to avoid performing attention on padding token indices. Mask values selected in `[0, 1]`:

        1 for tokens that are **not masked**,

        0 for tokens that are **masked**.

    * **token_type_ids** (`torch.LongTensor` of shape `(batch_size, sequence_length)`, optional) – Segment token indices to indicate first and second portions of the inputs. Indices are selected in `[0, 1]`:

        0 corresponds to a sentence A token,

        1 corresponds to a sentence B token.

* **answer** (`Optional[transformers.tokenization_utils_base.BatchEncoding]`, optional, defaults to None) - Answer data processed by tokenizer, similar to question.

### 视觉问答任务模型的forward输出


```python
{
  # 文本输出
  "text": "对于输入图片与问题模型输出的答案"
}
```

## 图文检索任务

图文检索属于跨模态检索，是跨模态理解中最为基础的任务，它以一种类型的数据作为查询去检索另一种类型的数据，以图像和文本两种模态为例，异构鸿沟是指由于图像和文本的表示形式不一致，两者数据处于不同的分布空间，无法直接度量相似性，因此是很有挑战性的任务。

# 模型的训练

mPLUG模型的训练可以使用ModelScope提供的trainer来进行。下面的代码展示了一个完整的模型训练过程：

```python
import tempfile
from modelscope.msdatasets import MsDataset
from modelscope.trainers import EpochBasedTrainer, build_trainer

# 使用 coco 数据集的一小部分数据进行训练
datadict = MsDataset.load('coco_captions_small_slice')

# 重命名数据集字段使于模型输入匹配
train_dataset = MsDataset(datadict['train'].to_hf_dataset().map(
        lambda _: {
            'question': 'what the picture describes?'
    }).rename_column('image:FILE',
                     'image').rename_column('answer:Value', 'answer'))
test_dataset = MsDataset(datadict['test'].to_hf_dataset().map(
        lambda _: {
            'question': 'what the picture describes?'
    }).rename_column('image:FILE',
                     'image').rename_column('answer:Value', 'answer'))

max_epochs = 3
tmp_dir = tempfile.TemporaryDirectory().name

# 可用此函数修改 trainer 运行中的 hook 行为
def _cfg_modify_fn(self, cfg):
    cfg.train.hooks = [{
        'type': 'CheckpointHook',
        'interval': max_epochs
    }, {
        'type': 'TextLoggerHook',
        'interval': 1
    }, {
        'type': 'IterTimerHook'
    }]
    return cfg

kwargs = dict(
    model='damo/mplug_visual-question-answering_coco_large_en',
    train_dataset=train_dataset,
    eval_dataset=test_dataset,
    max_epochs=max_epochs,
    work_dir=tmp_dir,
    cfg_modify_fn=_cfg_modify_fn)

# 构造 trainer 并进行训练
trainer: EpochBasedTrainer = build_trainer(
    name=Trainers.nlp_base_trainer, default_args=kwargs)
trainer.train()
```

训练后在work_dir中会存储训练过程文件（用于断点继续训练）和推理文件（用于上传modelhub或推理、导出等场景）。
训练的具体细节和产出文件的使用请参考[模型的训练文档](https://www.modelscope.cn/docs/%E6%A8%A1%E5%9E%8B%E7%9A%84%E8%AE%AD%E7%BB%83Train)。
